# specops-ostqaoa — Operator-Spectral Truncated Priors for Query-Efficient QAOA

Reference implementation and reproduction package for the manuscript
*Operator-Spectral Truncated Priors for Query-Efficient QAOA Parameter Search*
(Molena Huynh, North Carolina State University). From a single global seed it
regenerates every reported figure, table, CSV result, and per-query trace of a
set of deterministic exact-statevector MaxCut experiments. The package is part
of the author's single-author research program on spectral truncation of
operators for query-efficient quantum optimization.

- Distribution name: `specops-ostqaoa`
- Importable package: `ostqaoa`
- BibTeX key: `huynh2026ostqaoa`

---

## Background and problem setting

The Quantum Approximate Optimization Algorithm (QAOA) is a variational quantum
template for combinatorial graph problems such as MaxCut. At circuit depth `p`
the algorithm is controlled by a `2p`-dimensional angle vector
`θ = (γ₁,…,γ_p, β₁,…,β_p)`; for a graph `G` the algorithm prepares a state
`|ψ_G(θ)⟩` and the objective `f_G(θ) = ⟨ψ_G(θ)| H_C(G) |ψ_G(θ)⟩` is the expected
cut value. Quality is measured by the approximation ratio
`r_G(θ) = f_G(θ) / C_G⋆`, where `C_G⋆` is the exact optimum.

In the noisy intermediate-scale regime the practical bottleneck of low-depth
QAOA is **not** the circuit but the *classical outer loop*: the number of
expensive objective evaluations ("queries") spent tuning `θ` on each new
instance. A good warm-start point alone is insufficient — under a fixed query
budget the optimizer must also know *which angle directions* deserve
exploration. Existing angle-search priors sit at two extremes: a fixed-schedule
prior (e.g. the Trotterized-annealing / TQA schedule) supplies one
graph-independent point, and a diagonal prior refines each angle coordinate
independently. Neither emphasizes *collective, off-coordinate* angle directions.

This package addresses that gap by learning and searching in **operator space**
rather than in raw parameter-vector space, and treats the number of objective
queries as the currency to be economized. The design idea — finite-rank
noncommutativity as a tractable way to encode interaction — is transported from
the spectral-truncation-kernel framework for noncommutative C*-algebraic kernel
machines (Hashimoto et al., arXiv:2405.17823) into the variational-quantum
setting.

## Contributions

1. **A truncated, noncommuting operator on QAOA angle space.** Each graph is
   mapped to two symmetric `2p×2p` generators `A_G, B_G` (global spectral and
   local degree structure) that are *designed not to commute*; their commutator
   enters a single angle operator that is then spectrally truncated to a rank-`n`
   positive-semidefinite covariance. This replaces a scalar graph feature or a
   diagonal uncertainty vector with a full operator-valued, graph-conditioned
   prior.

2. **Operational use of off-diagonal structure.** The query policy probes the
   *collective* eigendirections of the covariance `Σ_G` rather than the raw
   angle coordinates. Restricting the search to diagonal (commutative) directions
   removes a measurable part of the advantage (−0.010 mean ratio), so the
   off-coordinate operator geometry is shown to be used, not assumed.

3. **A query-budget / truncation tradeoff with theory and a stated assumption.**
   The truncated prior is proved positive definite and Loewner-monotone in the
   rank, it reduces exactly to the commutative diagonal prior in the single-
   direction limit, and truncation caps the prior's effective dimension
   `d_eff(n)`. Under an explicitly stated coverage assumption a *heuristic*
   scaling argument links `d_eff(n)` to objective-query cost and predicts an
   interior optimum `n⋆`, which is then observed empirically.

4. **A reproducible, installable, multi-seed artifact.** Every figure, table,
   CSV, and query trace is regenerated by the package from a single seed, and the
   headline advantage is shown to hold across ten seeds. The package installs
   with `pip install .` and exposes both a CLI and a Python API for retuning
   every experimental parameter.

## Method

For a graph `G`, let `m_λ` be normalized-Laplacian spectral moments, `m_d`
centered degree moments (each of length `2p`), and `φ(G)` a normalized topology
descriptor. Two symmetric angle-space operators are formed,

```
A_G = Toeplitz(0.70·m_λ + 0.30·φ(G))                                (global spectrum)
B_G = sym[ roll·Toeplitz(0.55·m_d + 0.45·φ(G)_rev) ]                (local degree)
```

They are designed so that the commutator `C_G = [A_G, B_G] = A_G B_G − B_G A_G ≠ 0`,
encoding local/global coupling that no single symmetric generator captures. The
raw angle operator, with commutator weight `ω`, is

```
O_G = sym( 0.55·A_G + 0.45·B_G + ω·C_Gᵀ C_G ),
```

then **spectrally truncated** to rank `n`: `O_{G,n} = U_n Λ_n U_nᵀ` after
nonnegative clipping of the eigenvalues. The search covariance is
operator-dominated,

```
Σ_G = β·O_{G,n}/tr(O_{G,n}) + (1 − β/2)·Σ_nbr/tr(Σ_nbr) + ε·I,   (β = 0.8, ε = 0.025)
```

so the truncation rank `n` and the noncommuting operator geometry — not the
diagonal neighbour variances — set the probed directions. The posterior mean
`μ_G` blends a Gaussian-weighted mean of the `k` nearest training-library angles
(in operator-signature space) with the fixed TQA schedule. The **query policy**
is deterministic and auditable: build `O_{G,n}`, compute `(μ_G, Σ_G)`, evaluate
four anchors `{θ_TQA, μ_G, θ_nearest, θ_global}`, diagonalize
`Σ_G = V Λ Vᵀ`, and for scales `s ∈ {1.0, 0.55, 0.28}` evaluate incumbent
perturbations `±s·√λ_j·v_j` in descending-variance order until the query budget
`Q` is exhausted; the full query trace is returned.

The effective search dimension `d_eff(Σ) = (Σ_j λ_j)² / Σ_j λ_j²` (participation
ratio) is bounded above by `n + O(ε)`, so truncation caps the number of
collective directions probed, and the objective-query cost scales with `d_eff`
rather than with the ambient `2p`.

## Main results

Reference operating point: `p = 3`, `Q = 24`, truncation rank `4`, commutator
weight `ω = 4.0`, seed `260424803`; four graph families (Erdős–Rényi,
random-regular, Watts–Strogatz, Barabási–Albert) at `n ∈ {8, 10}`, six training
graphs and four held-out test graphs per family (16 paired held-out instances
per seed). All objectives are exact statevector expectations and all MaxCut
normalizers are exact brute-force optima.

- **Headline (single seed).** OST-QAOA reaches mean approximation ratio
  `0.820 ± 0.019`, `+0.112` over budget-matched TQA+coordinate (paired bootstrap
  95% interval `[+0.083, +0.142]`), winning on all `16/16` paired held-out
  graphs (sign-test `p < 10⁻⁴`). It reaches 98% of the best observed ratio in a
  mean of `10.1` objective queries against `25.0` for TQA+coordinate and `13.1`
  for the diagonal variant (`Q̄₀.₉₈`).
- **Robustness (ten seeds; 160 paired instances).** The paired gain over
  TQA+coordinate is `+0.107 ± 0.011`, positive on every seed (per-seed range
  `[+0.087, +0.126]`), with `157/160` instance wins. OST-QAOA reaches the target
  in a mean of `10.5` queries against `24.7` for the baseline — a `2.4×`
  reduction. Every graph family has a positive paired mean improvement, largest
  on Barabási–Albert (`+0.190`) and smallest on random-regular (`+0.035`).
- **Truncation sweep.** The predicted interior optimum appears: rank `n⋆ = 4`
  is best; aggressive truncation (`n = 1`) underfits and no truncation
  (`n = 2p = 6`) over-diffuses the covariance. The effective dimension rises
  monotonically from `2.50` at `n = 1` to `3.64` at `n = 6`.
- **Ablation.** Restricting the covariance to its diagonal (the commutative
  special case) drops the mean ratio by `0.010`, localizing the advantage to the
  off-diagonal, noncommuting search directions. The *explicit* squared-commutator
  energy term is near-neutral (`−0.003` at the operating point, sign-oscillating
  across ranks), which is reported rather than overclaimed.

## Significance

In low-depth QAOA the operationally relevant axis is the number of objective
queries, each of which is a full quantum-circuit execution or a costly classical
statevector simulation. OST-QAOA supplies both a graph-conditioned warm-start
point and, through the spectrally truncated rank-`n` covariance, the collective
cross-layer search directions themselves, yielding comparable solution quality in
roughly `2.4×` fewer objective queries. Conceptually, it demonstrates that
finite-rank noncommutativity — previously developed for supervised C*-algebraic
kernel machines — transfers to variational quantum optimization, where the
truncation parameter now trades near-optimal coverage against query cost rather
than approximation against generalization. The result is presented as a fully
reproducible, audit-sized method study, not a hardware-scale or asymptotic-
advantage claim.

## Installation and reproduction

From an artifact checkout:

```bash
cd submission/code
pip install .
```

Development install with the test extra:

```bash
pip install -e .[test]
```

Runtime requirements are Python ≥ 3.9 plus NumPy, SciPy, pandas, PyYAML,
NetworkX, matplotlib, and scikit-learn as constrained in `pyproject.toml`.

A single console command rebuilds all main-body figures and tables into the
`figures/` and `tables/` directories that `submission/main.tex` reads:

```bash
ostqaoa-reproduce --output-dir . \
  --depth 3 \
  --budget 24 \
  --rank 4 \
  --commutator-weight 4.0 \
  --seed 260424803
```

The `ostqaoa-reproduce` driver chains cooperating stages that all consume the
same deterministic CSVs: the matched-budget benchmark / truncation sweep /
ablation / per-family analysis (`ostqaoa.paper_artifacts`), the per-query trace
(`trace_evaluations.py`), the ten-seed robustness study
(`multiseed_robustness.py`), and the mirror figures plus the conceptual
prior-comparison table (`make_jmlr_mirror_artifacts.py`).

Fast package sanity check (reduced seeds/size, still runs the real pipeline):

```bash
ostqaoa-reproduce --quick --skip-multiseed --output-dir /tmp/ostqaoa-smoke
```

The matched-budget benchmark stage alone:

```bash
python -m ostqaoa.paper_artifacts \
  --output-dir . --depth 3 --budget 24 --rank 4 --commutator-weight 4.0 \
  --seed 260424803
```

### Python API

```python
from ostqaoa import build_operator_library, ost_qaoa_search
from ostqaoa.graphs import generate_graph

library = build_operator_library(p=3, rank=4, commutator_weight=4.0, train_per_family=6)
graph = generate_graph("random_regular", 10, 1234)
result = ost_qaoa_search(graph, library, budget=24)
print(result.y_hat, result.theta_hat)
```

## Extend / tweak

Every reported number is a deterministic function of the CLI flags below;
changing any of them regenerates all figures, tables, CSVs, and query traces.

### CLI flags (`ostqaoa-reproduce`)

| Option | Meaning | Manuscript value |
|--------|---------|------------------|
| `--depth` | QAOA depth `p` (angle-operator dimension is `2p`) | `3` |
| `--budget` | Matched objective-query budget per instance | `24` |
| `--rank` | Spectral-truncation parameter `n` of the angle operator | `4` |
| `--commutator-weight` | Noncommutative commutator interaction weight `ω` | `4.0` |
| `--seed` | Global deterministic seed | `260424803` |
| `--seeds` | Comma-separated seed list for the ten-seed study | 10 seeds |
| `--quick` | Reduced-size complete pass for CI/smoke checks | off |
| `--skip-multiseed` | Skip the slow ten-seed robustness stage | off |
| `--skip-trace` | Skip the per-query trace regeneration | off |

### Additional flags on the benchmark stage (`python -m ostqaoa.paper_artifacts`)

| Option | Meaning | Default |
|--------|---------|---------|
| `--families` | Comma-separated graph families | `er,random_regular,watts_strogatz,barabasi_albert` |
| `--sizes` | Comma-separated graph sizes (qubits) | `8,10` |
| `--train-per-family` | Training-library graphs per family | `6` |
| `--test-per-family` | Held-out test graphs per family | `4` |
| `--optimizer-budget` | Offline optimizer budget for library targets | `42` |

### How to add a new graph family / input

Graph generation lives in `ostqaoa/graphs.py` (`generate_graph(family, n, seed)`).
Add a branch there for a new `family` string returning a `GraphInstance`, then
pass it via `--families`. Graph descriptors used by the prior generators are in
`graph_features`; extend that to feed new mechanistic structure into
`build_operator_library`.

### How to add a new prior / baseline

Baselines (`random`, `tqa`, `tqa+coordinate`, `knn+coordinate`) live in
`ostqaoa/baselines.py` and are dispatched in
`ostqaoa/operator_spectral.py::evaluate_methods_on_graph`. Add a callable with
the shared `SearchResult` return type and register it there to have it appear in
the headline table and query curves.

### How to add a new tunable parameter

Numeric experiment knobs are validated in `ostqaoa/config.py`
(`ExperimentConfig`). Add a field there, thread it through
`build_operator_library` / `ost_qaoa_search`, and expose it as an
`add_argument` in `paper_artifacts.py` (and, if it should be reachable from the
one-shot driver, in `full_reproduce.py`).

### Plug into another project

Import `build_operator_library` once (offline training), then call
`ost_qaoa_search(graph, library, budget=...)` per new graph to obtain the
budgeted angle estimate `theta_hat` and its expected approximation ratio
`y_hat`. The library is backend-agnostic: the query policy in
`operator_spectral.py` is independent of the statevector backend in
`statevector.py`, so an external evaluator (finite-shot or hardware) can be
substituted for `qaoa_expectation`.
